# Environment Setup and CLI Quickstart

This guide walks through configuring your environment, preparing local PostgreSQL persistence, and running the Harness CLI.

---

## 1. Prerequisites

- **Bun**: v1.3.14+ (`curl -fsSL https://bun.sh/install | bash`)
- **Docker**: For running a local PostgreSQL container (or a native PostgreSQL 16+ installation)

---

## 2. Environment Configuration

Copy the template configuration file:

```bash
cp .env.example .env
```

Review and update the variables in `.env`:

| Variable | Description | Default / Example |
|---|---|---|
| `DATABASE_URL` | PostgreSQL connection string | `postgresql://harness:harness@localhost:5432/harness` |
| `PROVIDER_NAME` | Model provider identifier | `openai` (or `anthropic`, `google`, `openrouter`) |
| `MODEL_NAME` | Model identifier | `gpt-4o-mini` |
| `MODEL_API_KEY` | Provider API authentication key | `sk-...` |
| `MODEL_TIMEOUT_MS` | Per-attempt timeout in ms | `30000` (min: 1000, max: 300000) |
| `MODEL_MAX_OUTPUT_TOKENS` | Max tokens generated by model | `4096` (min: 1, max: 32768) |

> **Security Note**: Never commit `.env` containing real API keys or passwords. Harness automatically masks credentials in logs, CLI output, and trajectory events.

---

## 3. Local PostgreSQL Setup

### Option A: Using Docker (Recommended)

Start a local PostgreSQL container:

```bash
docker run --name harness-postgres \
  -e POSTGRES_USER=harness \
  -e POSTGRES_PASSWORD=harness \
  -e POSTGRES_DB=harness \
  -p 5432:5432 \
  -d postgres:16-alpine
```

To stop and start the container later:

```bash
docker stop harness-postgres
docker start harness-postgres
```

### Option B: Local PostgreSQL Service

Ensure a database named `harness` exists and is accessible via the URL specified in your `.env`.

---

## 4. Database Migrations

Once PostgreSQL is up and running, generate and apply database migrations via Track C schema tools:

```bash
# Apply migrations to database
bun run --cwd packages/schema db:migrate
```

## 5. CLI Usage

The workspace root provides delegated npm/bun scripts to invoke CLI commands directly.

### Running a Prompt (`cli:run`)

Submit a prompt for evaluation by the model runner:

```bash
bun run cli:run -- --prompt "Explain smart contract reentrancy vulnerabilities and prevention"
```

You can optionally override the model or timeout flags:

```bash
bun run cli:run -- --prompt "Summarize ERC-20 invariants" --model gpt-4o --timeout 20000
```

#### Output Fields:
- **Run ID**: Unique identifier assigned to the run execution (`run-<hash>`).
- **State**: Execution state (`completed` or `failed`).
- **Model**: Model invoked.
- **Latency**: End-to-end execution latency in milliseconds.
- **Tokens**: Total tokens used, split into prompt and completion tokens.
- **Cost**: Estimated cost in USD.
- **Model Output**: Sanitized model response.

### Inspecting Historical Runs (`cli:view`)

Query a past run record and chronological trajectory events by its Run ID:

```bash
bun run cli:view -- --id run-c49c71a3962b
```

#### Output Fields:
- **Run ID** & **State**: Technical run lifecycle state and version.
- **Trajectory Events**: Chronologically ordered events including timestamps, event types, and scrubbed payload parameters.

### Viewing Help

```bash
bun run cli:run -- --help
# or
bun run cli:view -- --help
```
