# Spec Delta

## MODIFIED Requirements

### Requirement: PostgreSQL relational schema and migrations
The persistence layer SHALL provide a relational schema managed via Drizzle ORM and SQL migrations with three core tables: `runs`, `events`, and `model_attempts`.
- `runs` MUST record `id` (text primary key), `prompt` (text), `state` (varchar: `pending`, `running`, `completed`, `failed`), `state_version` (integer optimistic concurrency version), `model_profile` (varchar), `result_content` (text nullable), `error_message` (text nullable), `prompt_tokens` (integer nullable), `completion_tokens` (integer nullable), `cost_usd` (numeric nullable), `latency_ms` (integer nullable), `created_at` (timestamp), `updated_at` (timestamp), optional `terminal_reason` (varchar nullable), and optional `snapshot_id` (text nullable) recording the immutable snapshot identity the run analyzed. `snapshot_id` MUST be an opaque snapshot identity, never a host path.
- `events` MUST record `id` (text primary key), foreign key `run_id` referencing `runs(id)`, `sequence` (integer), `event_type` (varchar), `payload` (jsonb), `payload_digest` (varchar), and `timestamp` (timestamp), with a composite uniqueness constraint on `(run_id, sequence)` guaranteeing an ordered, contiguous event trajectory.
- `model_attempts` MUST record `id` (text primary key), `run_id` (foreign key referencing `runs(id)`), `attempt_number` (integer), `provider` (varchar), `model` (varchar), `prompt_tokens` (integer), `completion_tokens` (integer), `total_tokens` (integer), `cost_usd` (numeric), `latency_ms` (integer), `finish_reason` (varchar nullable), `request_json` (jsonb), `response_json` (jsonb nullable), `error_message` (text nullable), `error_category` (varchar nullable), `created_at` (timestamp), and the per-turn identity fields `step_index` (integer) and `attempt_purpose` (varchar: `reasoning` or `compaction`). A provider attempt MUST be uniquely identified by `(run_id, step_index, attempt_purpose, attempt_number)`, enforced by a unique constraint, and recording an attempt MUST be idempotent (`ON CONFLICT (run_id, step_index, attempt_purpose, attempt_number) DO NOTHING`) so a retry or worker redelivery stores each attempt exactly once and a purpose value outside the allowed set is rejected.
Database migrations MUST be reproducible via SQL migration files generated by `drizzle-kit` and executable via `bun run --cwd packages/schema db:migrate`.

#### Scenario: Running database migration creates relational tables
- **WHEN** the migration command `bun run --cwd packages/schema db:migrate` is executed against an accessible PostgreSQL database
- **THEN** tables `runs`, `events`, and `model_attempts` are created with the specified columns, data types, foreign keys, and uniqueness constraints, including `runs.snapshot_id` and the `model_attempts` per-turn identity fields.

#### Scenario: Run links to the snapshot it analyzed
- **GIVEN** a run created for an immutable snapshot
- **WHEN** the run record is read back
- **THEN** it carries the opaque snapshot identity and no host path

#### Scenario: Multi-turn attempts are stored once and in order
- **GIVEN** a run that made several provider attempts across steps
- **WHEN** the attempt records are read back
- **THEN** each `(run_id, step_index, attempt_purpose, attempt_number)` appears exactly once and the attempts can be ordered by step index

#### Scenario: Duplicate or unknown purpose is refused
- **GIVEN** an attempt record whose `(run_id, step_index, attempt_purpose, attempt_number)` already exists, or whose `attempt_purpose` is neither `reasoning` nor `compaction`
- **WHEN** the record is written
- **THEN** a duplicate write affects no row and a purpose value outside the allowed set is rejected
